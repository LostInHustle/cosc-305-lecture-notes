# Part 1: Project Planning

## 3. The 5 Main Project Management Process Groups

A project is commonly organized into 5 major process groups:

1. Initiating

2. Planning

3. Executing

4. Monitoring and controlling

5. Closing

These groups represent the general progression of a project.

Monitoring and controlling often occurs at the same time as execution because the project manager must continually compare actual performance with the plan.

## 4. The Initiating Process Group

The initiating process group establishes the basic direction of the project.

During initiation, the organization should:

1. Define the project objectives.

2. Identify the problem or opportunity.

3. Conduct a preliminary feasibility study.

4. identify a proposed solution.

5. Describe the expected product, service, or result.

6. Establish an initial schedule.

7. Establish a preliminary budget.

8. Identify important stakeholders.

9. Assign or authorize the project manager.

10. Decide whether the project should continue.

The final decision is often described as a go or no go decision.

If the organization approves the project, resources and funding can be committed and detailed planning can begin.

## 5. The Project Charter

A major output of initiation is the project charter.

The project charter is not the complete project plan. It is a high level document that formally authorizes the project.

A project charter normally includes:

1. Project purpose

2. Project objectives

3. High level requirements

4. Proposed solution

5. Initial scope

6. Major milestones

7. Preliminary budget

8. Important risks and assumptions

9. Key stakeholders

10. Project manager authority

The charter provides enough information for decision makers to determine whether the project should proceed.

Once approved, the charter gives the project manager formal authority to use organizational resources for project activities.

## 6. The Planning Process Group

After initiation, the project enters planning.

Planning is one of the project manager's main responsibilities.

The project manager begins with the high level information in the project charter and develops a detailed and coordinated plan.

The planning process explains:

1. What work must be completed

2. How the work will be completed

3. Who will complete the work

4. When the work will be completed

5. How much the work will cost

6. What resources will be required

7. What quality standards will apply

8. How communication will occur

9. What risks may affect the project

10. How suppliers and external services will be managed

11. How stakeholders will be involved

## 7. Major Areas of Project Planning

The project manager develops several connected planning components.

### 7.1 Integration Planning

Integration planning coordinates all parts of the project.

It ensures that the individual plans work together as one consistent project management plan.

The project manager must resolve conflicts between areas such as scope, schedule, cost, quality, and resources.

### 7.2 Scope Planning

Scope planning defines what the project will and will not include.

It answers 2 important questions:

1. What is inside the project scope?

2. What is outside the project scope?

Clear scope boundaries help prevent misunderstandings, uncontrolled expansion, and unnecessary work.

A major output of scope planning is the work breakdown structure.

### 7.3 Work Breakdown Structure

The work breakdown structure divides the total project scope into smaller and more manageable components.

It helps the project manager and team:

1. Understand the complete body of work.

2. Identify specific deliverables.

3. Estimate time and cost.

4. Assign responsibility.

5. Develop the project schedule.

6. Monitor progress.

The work breakdown structure is important because later planning activities depend on a clear understanding of the required work.

### 7.4 Schedule Planning

Schedule planning determines when project activities should occur.

It includes:

1. Identifying activities

2. Determining activity relationships

3. Estimating activity durations

4. Identifying milestones

5. Assigning resources

6. Developing the project schedule

7. Establishing the planned completion date

The schedule is based on the work identified during scope planning.

### 7.5 Cost Planning

Cost planning estimates the financial resources required to complete the project.

It includes:

1. Estimating activity costs

2. Developing the project budget

3. Establishing an approved cost baseline

4. Planning how costs will be monitored

A project can spend more during a particular week while still remaining within its total budget if it finishes earlier or reduces costs later.

For this reason, project managers should examine both current spending and total projected spending.

### 7.6 Quality Planning

Quality planning defines the standards that the project's deliverables must meet.

It considers:

1. Customer expectations

2. Technical requirements

3. Acceptance criteria

4. Testing methods

5. Review procedures

6. Improvement activities

Quality should be planned from the beginning rather than inspected only at the end.

### 7.7 Resource Planning

Resource planning identifies the people, equipment, facilities, materials, and services required for the project.

It includes:

1. Determining team size

2. Identifying required skills

3. Assigning responsibilities

4. Planning training

5. Estimating resource availability

6. Deciding whether external support is necessary

The project manager must balance resource cost, skill level, workload, and productivity.

### 7.8 Communication Planning

Communication planning determines how project information will be created, shared, stored, and discussed.

It addresses:

1. Who needs information

2. What information each stakeholder needs

3. When information should be delivered

4. Which communication method should be used

5. Who is responsible for delivering the information

As team size increases, communication becomes more complex.

Outsourcing can create additional communication challenges because external teams may have different priorities, work practices, locations, time zones, and organizational cultures.

### 7.9 Risk Planning

Risk planning identifies uncertain events that could affect the project.

The project manager should:

1. Identify possible risks.

2. Estimate their probability and impact.

3. Prioritize the most important risks.

4. Develop response strategies.

5. Assign risk owners.

6. Monitor risks throughout the project.

Experience helps project managers recognize warning signs earlier, but simulations can provide a safe environment for developing this skill.

### 7.10 Procurement Planning

Procurement planning determines what products or services should be obtained from outside the organization.

It includes:

1. Deciding what should be purchased or outsourced

2. Identifying possible suppliers

3. Defining contract requirements

4. Evaluating cost and quality

5. Planning supplier communication

6. Monitoring external work

Outsourcing is especially useful when the internal team lacks a specialized skill or when an external provider can complete a task more efficiently.

### 7.11 Stakeholder Planning

Stakeholder planning identifies people and groups who can affect the project or be affected by it.

The project manager should understand:

1. Stakeholder expectations

2. Stakeholder influence

3. Stakeholder concerns

4. Required communication

5. Appropriate engagement strategies

Stakeholder identification begins during initiation and continues throughout the project.

## 8. Recommended Planning Sequence

Planning activities should usually follow a logical sequence because the output of one activity becomes an input to another.

A simplified planning sequence is:

1. Review the project charter.

2. Confirm project objectives.

3. Identify stakeholders.

4. Define the project scope.

5. Create the work breakdown structure.

6. Identify project activities.

7. Arrange activities in a logical order.

8. Estimate activity durations.

9. Estimate required resources.

10. Develop the schedule.

11. Estimate costs.

12. Establish the budget.

13. Define quality requirements.

14. Plan communication.

15. Identify and analyze risks.

16. Plan procurement and outsourcing.

17. Plan stakeholder engagement.

18. Integrate all components into the project management plan.

19. Review the plan for conflicts or unrealistic assumptions.

20. Obtain approval before execution begins.

The exact planning approach may vary by organization and project, but the plans must remain coordinated.

## 9. Moving from Planning to Execution

Execution should begin after the project management plan has been sufficiently developed and approved.

During execution, the team performs the planned work and creates the project's deliverables.

Monitoring and controlling occurs throughout execution.

The project manager compares actual performance with the approved plan and responds to differences involving:

1. Scope

2. Schedule

3. Cost

4. Quality

5. Resources

6. Communication

7. Risk

8. Procurement

9. Stakeholder expectations

# Part 2: Simulation Reflection

## 10. Simulation Performance

The class reviewed the leaderboard from the first project management simulation.

Approximately 26 students achieved a score of 800 or higher out of a class of about 65 students.

This represents approximately 40 percent of the class.

The top performers used different strategies, which shows that a project can sometimes be completed successfully through more than one management approach.

The first scenario was relatively manageable. Future scenarios are expected to require more active decision making and adjustment.

## 11. Common High Performing Strategy

A common strategy among successful students included:

1. Selecting a more ambitious project scope.

2. Using a team of approximately 4 or 5 people.

3. Selecting medium skill team members.

4. Using extensive outsourcing where appropriate.

5. Setting an earlier target completion date.

6. Providing more meetings and support near the beginning.

7. Reducing meetings after the team became comfortable.

8. Monitoring team productivity and workload.

9. Adjusting the team near the end of the project.

10. Finishing early enough to earn schedule related benefits.

Successful students often accepted a higher weekly cost because completing the project earlier reduced the number of weeks during which resources had to be paid.

## 12. Scope Selection

Several students found that choosing a higher scope level produced a better total score.

A higher scope level increased the amount of work, but it also created an opportunity to earn additional points.

The important lesson is not that a project manager should automatically select the largest possible scope.

The lesson is that the project manager must understand how success is measured and choose a scope that creates value without becoming unmanageable.

In a real project, any scope increase should be evaluated and formally approved.

## 13. Budget Interpretation

Some students initially believed they were exceeding the budget because the dashboard showed high weekly spending.

However, weekly spending does not always determine the final budget result.

A project may have high weekly costs but still achieve an acceptable total cost if it finishes early.

Project managers should therefore distinguish between:

1. Current spending

2. Weekly spending rate

3. Total spending to date

4. Estimated cost at completion

5. Remaining budget

6. Expected project duration

A single dashboard signal should not be interpreted without considering the larger project context.

## 14. Schedule Strategy

Students who earned strong scores frequently used an aggressive but achievable target completion date.

For example, a project with an official deadline of 18 weeks might be managed with an internal target of 14 or 15 weeks.

An earlier target can encourage the team to maintain a productive pace.

However, an unrealistic target can create excessive pressure and reduce performance.

The project manager must find a balance between urgency and overload.

## 15. Team Size

A stable team of approximately 4 people was effective for several students.

Some students increased the team size near the end when additional capacity was needed to finish the remaining work.

Others reduced the team size during the final week when only a small amount of work remained.

Changing team size can affect:

1. Cost

2. Productivity

3. Communication

4. Training requirements

5. Team familiarity

6. Coordination effort

Frequent hiring and removal of team members may create transition costs because new members need time to understand the project.

## 16. Skill Level and Training

Medium skill team members were effective in many successful simulation attempts.

Some students provided intensive training or individual support early in the project.

Once team members understood the work, the students reduced the amount of training and supervision.

This approach allowed the team to use more time for productive tasks later.

Training has an immediate cost, but it may produce benefits across several future weeks.

## 17. Meeting Strategy

Meetings were one of the most frequently adjusted simulation variables.

Many successful students used more meetings at the beginning and fewer meetings later.

Early meetings helped the team understand:

1. Project objectives

2. Individual responsibilities

3. Team responsibilities

4. Current problems

5. Priorities

6. Expected progress

Once the team became familiar with the work, excessive meetings reduced the time available for completing tasks.

The general pattern was:

1. Begin with stronger communication.

2. Observe team feedback and productivity.

3. Reduce unnecessary meetings once the team becomes stable.

4. Add targeted meetings when a specific problem appears.

## 18. Types of Meetings

Different meetings addressed different needs.

### Standup Meetings

Standup meetings helped team members understand what other people were doing.

They were useful when the team experienced coordination problems.

### Individual Meetings

Individual meetings provided personal coaching, clarification, and support.

They were useful when a specific team member lacked confidence, training, or direction.

### Status Reviews

Status reviews helped the team understand overall progress, priorities, and expectations.

They were useful when team members lacked information about project performance or changing objectives.

The project manager should select a meeting type based on the actual communication problem rather than simply increasing every type of meeting.

## 19. Proactive and Reactive Management

Students used both proactive and reactive approaches.

### Proactive Approach

A proactive manager anticipates problems and acts before they become serious.

Examples include:

1. Providing additional training at the beginning

2. Scheduling early prototypes

3. Setting a realistic internal deadline

4. Planning communication before confusion appears

5. Identifying likely outsourcing risks

### Reactive Approach

A reactive manager waits for a warning signal and responds after the problem appears.

Examples include:

1. Adding meetings after morale declines

2. Reducing outsourcing after communication problems emerge

3. Increasing the team after the schedule falls behind

4. Providing training after productivity decreases

Reactive management is sometimes necessary, but constant reaction can make the project unstable.

A strong project manager plans proactively while remaining ready to respond to unexpected events.

## 20. Team Morale

Low morale can reduce productivity, increase errors, and create retention problems.

However, students observed that temporary dissatisfaction did not always cause the simulation to fail.

This does not mean morale should be ignored.

A project manager should examine:

1. How severe the morale problem is

2. How long it has continued

3. Whether productivity is declining

4. Whether the team is overworked

5. Whether the team lacks information

6. Whether the problem is temporary or persistent

7. Whether intervention will help

In a real organization, repeatedly exhausting employees can lead to burnout, conflict, lower quality, and employee turnover.

A strategy that earns a strong simulation score may not be ethical, sustainable, or effective in a real workplace.

## 21. Workload Versus Morale

One student tested several simulation runs and found that excessive workload had a greater effect on productivity than moderate dissatisfaction.

When the team was seriously overworked, completed tasks decreased substantially.

When team members were dissatisfied but not overloaded, the productivity decrease was smaller.

The broader lesson is that project managers should measure the actual effect of each condition.

Different issues can produce different levels of impact.

## 22. Controlled Experimentation

One student used a structured testing approach.

The student completed several trial simulations and changed one factor at a time.

The process was:

1. Establish a consistent starting configuration.

2. Select one variable to change.

3. Run the simulation for several weeks.

4. Record productivity and team reactions.

5. Compare the result with earlier attempts.

6. Identify which variable produced the greatest effect.

7. Focus management attention on the most important variables.

This is a useful analytical approach because changing many factors at once makes it difficult to determine which change caused the result.

## 23. Outsourcing

Outsourcing can increase capacity and provide access to specialized skills.

Suitable outsourcing candidates may include:

1. Specialized security work

2. Complex system integration

3. Data conversion

4. Data cleaning

5. Repetitive processing

6. Tasks outside the team's expertise

7. Independent supporting tasks

However, outsourcing can create problems involving:

1. Communication

2. Coordination

3. Quality control

4. External priorities

5. Organizational culture

6. Business practices

7. Time differences

8. Dependence on another organization

Core activities with many dependencies may be more difficult to outsource successfully.

Supporting tasks with clear requirements and limited connections to other work may be easier to assign externally.

## 24. Remote Work and Informal Communication

In person teams often exchange information through informal conversations.

Examples include discussions during:

1. Breaks

2. Lunch

3. Work sessions

4. Informal desk conversations

5. Unplanned problem solving

These interactions can help teams notice issues and make decisions quickly.

Remote and outsourced teams may not receive the same informal information.

Project managers must therefore create intentional communication opportunities without overwhelming the team with meetings.

## 25. Prototypes

Prototypes helped teams clarify requirements, identify problems, and understand the expected solution.

After a prototype was completed, team morale and productivity sometimes improved because uncertainty decreased.

The benefits of prototypes include:

1. Making ideas visible

2. Discovering misunderstandings

3. Receiving earlier feedback

4. Identifying technical problems

5. Improving stakeholder confidence

6. Reducing uncertainty

The cost is that prototypes require time and resources.

Too many prototypes may delay the final product.

The project manager must choose a useful number and schedule them at meaningful points.

## 26. Monitoring Signals

The simulation provided several signals, including:

1. Budget status

2. Schedule status

3. Team morale

4. Workload

5. Productivity

6. Communication complaints

7. Training needs

8. Completed tasks

9. Problems discovered

10. Expected completion date

Not every signal has the same importance at every moment.

A project manager should ask:

1. Is this signal accurate?

2. Is it temporary or persistent?

3. Does it affect project objectives?

4. What will happen if it is ignored?

5. What is the cost of responding?

6. Is another signal more urgent?

7. Does the proposed response create a new problem?

Ignoring every warning is irresponsible, but reacting to every small fluctuation can also damage the project.

## 27. Reading the Scenario Description

The scenario description provides important planning information.

Students should not skip comments about:

1. Budget realism

2. Schedule difficulty

3. Requirement stability

4. Resource availability

5. Competitive pressure

6. Management priorities

7. Expected project complexity

8. Known limitations

These comments provide early intelligence about possible risks.

A good project manager collects as much relevant information as possible before creating the plan.

## 28. Requirements and Alternatives

The lecture suggested that project managers should not follow every initial request without analysis.

This point requires careful interpretation.

Project managers should not secretly ignore approved requirements.

Instead, they should:

1. Determine whether the requirements are feasible.

2. Identify conflicts between scope, time, cost, and quality.

3. Explain the consequences to decision makers.

4. Propose realistic alternatives.

5. Negotiate priorities.

6. Obtain approval for changes.

7. Document the agreed solution.

If the original request cannot be completed within the available budget and schedule, the project manager should negotiate an alternative rather than silently changing the project.

## 29. Simulation Results Versus Real Management

The simulation rewards certain measurable outcomes, such as:

1. Completing more scope

2. Finishing earlier

3. Controlling total cost

4. Maintaining productivity

5. Responding to team conditions

However, the simulation cannot reproduce every consequence found in a real workplace.

A simulation strategy may produce a high score while creating unacceptable real world effects.

Examples include:

1. Excessive employee stress

2. Repeated hiring and removal of staff

3. Unsustainable workloads

4. Poor long term retention

5. Reduced trust

6. Lower quality

7. Ethical concerns

Students should use the simulation to understand relationships between variables, not as proof that every successful simulation strategy should be copied in a real organization.

## 30. Project Manager Accountability

The project manager is responsible for coordinating the project and responding to important risks.

If the project fails, senior leaders and stakeholders will expect the project manager to explain:

1. What happened

2. Why it happened

3. Which warning signs appeared

4. What actions were taken

5. Why those actions were selected

6. What should be improved

The project manager does not personally perform every task, but remains accountable for coordinating the overall effort.

## 31. Lessons from the Simulation

The main lessons are:

1. Understand how project success is measured.

2. Read the scenario description carefully.

3. Do not rely on a single dashboard signal.

4. Compare weekly cost with total projected cost.

5. Use ambitious but achievable schedule targets.

6. Monitor workload as well as morale.

7. Use meetings for specific purposes.

8. Reduce unnecessary meetings when the team becomes stable.

9. Use outsourcing strategically.

10. Consider the communication cost of outsourcing.

11. Use prototypes to reduce uncertainty.

12. Test assumptions through controlled experiments.

13. Change one major variable at a time when investigating performance.

14. Distinguish temporary problems from serious trends.

15. Avoid reacting to every minor warning.

16. Do not ignore critical warning signs.

17. Negotiate when the original requirements are not feasible.

18. Obtain approval before changing project scope or objectives.

19. Remember that simulation success may not equal sustainable real world management.

20. Learn from each project and apply the experience to future planning.

## 32. Practical Planning Checklist for Upcoming Projects

Use the following process when planning future projects:

1. Read the complete project description.

2. Identify the project's purpose.

3. Define measurable objectives.

4. Identify all important stakeholders.

5. Clarify the required scope.

6. Record what is outside the scope.

7. Create the work breakdown structure.

8. Identify activities and dependencies.

9. Estimate durations.

10. Determine required skills and resources.

11. Select an appropriate team size.

12. Decide which tasks may be outsourced.

13. Develop the schedule.

14. Set an achievable internal target date.

15. Estimate weekly and total costs.

16. Establish the budget.

17. Define quality standards.

18. Plan training and early support.

19. Select appropriate meeting types.

20. Plan prototypes and review points.

21. Identify risks and warning signals.

22. Define responses for major risks.

23. Confirm how success will be evaluated.

24. Review the complete plan for conflicts.

25. Obtain approval before starting execution.

26. Monitor actual results against the plan.

27. Adjust the approach when evidence shows that a change is necessary.

28. Document important decisions and approved changes.

29. Review lessons learned after completion.

## 33. Final Takeaway

Project planning is not merely the creation of a schedule.

It is the process of coordinating scope, time, cost, quality, resources, communication, risk, procurement, and stakeholder expectations.

The simulation demonstrated that successful project management requires judgment.

A strong project manager gathers information, tests assumptions, identifies the most important signals, communicates clearly, negotiates realistic alternatives, and makes informed adjustments without losing sight of the project's objectives.
